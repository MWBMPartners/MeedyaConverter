# Codex catch-up review, round 1 (2026-09-24)

Reviewer: Codex (`codex exec -s read-only -c model="gpt-6-astra"`), read-only.
Range: `02a5964..cd6b5a4`, i.e. all the 17–24 Sept work, which until now had been checked only by Claude reviewers.
Brief: `.claude/reviews/codex-2026-09-24-r1-brief.txt`. Findings are below, verbatim.
Each one is checked against the code before any fix. The verdicts are recorded in `.claude/HANDOFF.md`.

1. **BLOCKER — Privacy settings can be revoked before an upload, yet the upload still happens.** [DiscIdentifyViewModel.swift:228](<Sources/MeedyaConverter/ViewModels/DiscIdentifyViewModel.swift:228>) captures the enabled configuration and submission mode before reading the disc. Start identification with publishing enabled and `full`, then disable publishing or select anonymous while reading or looking up the disc. The later upload still uses the captured configuration and sends the label. The video identification path has the same issue at `MakeMKVRipViewModel.swift:702`.

2. **MAJOR — Saving one provider’s key can make another provider’s key disappear.** [MeedyaDBSettingsTab.swift:48](<Sources/MeedyaConverter/Views/MeedyaDBSettingsTab.swift:48>) and `SettingsView.swift:309` retain separate `APIKeyManager` instances. Each loads the shared index once and rewrites its entire cached index on mutation. Visit both tabs, save a TMDB key, then save a MeedyaDB key through the older instance: the latter can overwrite the index without the TMDB entry. Subsequent lookups cannot find that credential.

3. **MAJOR — Rip can use titles from a different source.** [MakeMKVRipViewModel.swift:441](<Sources/MeedyaConverter/ViewModels/MakeMKVRipViewModel.swift:441>) resolves the current source but uses selections from the last scan. Scan ISO A, change the source to ISO B without scanning, then press Rip. It extracts B using A’s title indices—or `all` when every title from A was selected. Source edits neither invalidate the scan nor block this operation.

4. **MAJOR — Cancellation before process launch is lost.** [MakeMKVExecutor.swift:324](<Sources/ConverterEngine/Disc/MakeMKVExecutor.swift:324>) always proceeds to `proc.run()`. If cancellation arrives before launch, `terminate()` sees `isRunning == false` and returns without recording cancellation. The process subsequently launches and runs until completion despite Cancel or navigation away.

5. **MAJOR — Process termination can discard scan output.** [MakeMKVExecutor.swift:326](<Sources/ConverterEngine/Disc/MakeMKVExecutor.swift:326>) removes the stdout handler and resumes completion without draining the pipe or waiting for an active callback. When MakeMKV writes its final records and exits before the reader finishes, titles or attributes disappear from a successful scan. Flushing the assembler only handles bytes already delivered to it.

6. **MAJOR — Fuzzy music matches are presented and submitted as exact identities.** [MusicBrainzDiscLookup.swift:141](<Sources/ConverterEngine/Disc/MusicBrainzDiscLookup.swift:141>) always uses `/discid/-`, which explicitly requests a [fuzzy TOC search](https://musicbrainz.org/doc/MusicBrainz_API#discid), bypassing the calculated Disc ID. If an unknown disc has one approximately matching release, the app says “Identified as” and `MeedyaDBSubmissionBuilder.swift:173` submits that candidate with confidence `1.0`.

7. **MAJOR — Physical Enhanced CDs cannot deliver the advertised whole-disc identity.** [DiscIdentifyViewModel.swift:86](<Sources/MeedyaConverter/ViewModels/DiscIdentifyViewModel.swift:86>) reads only the default first session; the CLI does likewise. The parser supplies no session table or second-session tracks. Insert a normal CD-Extra disc: identification sees only its audio session, reports it as single-session, and produces no distinct whole-disc contribution. The Enhanced CD helpers work with constructed inputs, but the production reader never supplies the required information.

8. **MAJOR — Label cleaning removes meaningful title numbers.** [TMDBDiscCandidates.swift:106](<Sources/ConverterEngine/Disc/TMDBDiscCandidates.swift:106>) strips every trailing numeric token. `APOLLO_13` becomes `APOLLO`; `FRIDAY_THE_13TH_PART_8` loses its sequel number. Those searches mix different films and can omit the intended film from the candidates being ranked. The year-filter retry never restores the removed title text.

9. **MINOR — MakeMKV’s quoted strings are parsed using the wrong escaping rules.** [MakeMKVBackend.swift:413](<Sources/ConverterEngine/Disc/MakeMKVBackend.swift:413>) handles doubled quotes, whereas MakeMKV specifies [backslash escaping](https://www.makemkv.com/developers/usage.txt). For example, `CINFO:2,0,"A \"B,C\""` is split into extra fields and the disc name is truncated. This corrupts displayed names, lookup seeds and diagnostic messages.

10. **MINOR — Adding a key can leave “nothing will be sent” displayed immediately before a contribution.** [DiscIdentifyView.swift:51](<Sources/MeedyaConverter/Views/DiscIdentifyView.swift:51>) observes the enabled switch and server address, but not credential changes. Open identification with publishing enabled and a URL but no key; save only the key in Settings. The notice remains “not configured,” while Identify rereads the key and contributes. The MakeMKV screen has the same missing refresh.

11. **MINOR — The screen and documentation promise television and comparisons that are not implemented.** [MakeMKVRipView.swift:276](<Sources/MeedyaConverter/Views/MakeMKVRipView.swift:276>) promises to identify a film or programme using chapters and languages; `docs/Disc-Tools.md:159` and the bundled help repeat this. Scan a television box set: the provider searches only movies. Ranking compares runtime, title and year; it never compares chapters or languages.

TOTAL: 11 findings.
